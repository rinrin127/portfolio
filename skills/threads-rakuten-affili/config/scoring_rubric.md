# scoring_rubric.md — 事前採点5軸100点（threads-post-analysis互換）

STEP Cで投稿**前**に適用する。事後分析（threads-post-analysisスキル）と同じ軸を使うことで、
予測スコアと実績スコアの差分から採点精度自体も週次で改善できる。

## 5軸（各20点）

1. **フック力**（1行目だけ読んで指が止まるか／数字・具体性・型への適合）
2. **ターゲット適合**（persona.mdの悩み・生活文脈に刺さるか）
3. **購買理由の説得力**（レビュー由来の事実が「欲しい理由」に変換されているか）
4. **読みやすさ**（200〜350字／改行リズム／絵文字3個以下／1投稿1商品1メッセージ）
5. **CTA自然度**（宣伝臭の弱さ／リンクへの導線が本文の流れと繋がっているか）

## 判定

- 80点以上 → 承認キューに「★推奨」で掲載
- 60〜79点 → 最低軸を1つ特定して自動リライト→再採点（1回のみ）
- 60点未満 → 破棄（キューに載せない）

## 採点時の減点ルール

- 断定的効果効能の気配（コンプラ検査前でも採点で弾く）: 軸3から-10
- フック型テンプレの丸写し（商品固有の数字・事実が入っていない）: 軸1から-10
- 「それな」等の空フレーズ: 軸4から-10（v4継承ルール：共感テロップ禁止）

## 比較モードの採点（スレッド全体を1本として採点）

親＋ぶら下げ3本を**合算して1投稿として**5軸で採点する。加えて以下を適用：

- 3商品すべてに「向いていない人」が書かれていない: 軸3から-15（比較の信用はここで決まる）
- 勝者を1つに断定している: 軸3から-10（他2リンクが死ぬ＝収益設計と矛盾）
- `【ここに体験：〜】`が3か所未満: 軸2から-10（りんりんの言葉が入る余地が無い）
- 数値を`【要確認：〜】`にせず断定している: 軸3から-20（捏造。この時点で破棄）

プレースホルダは**減点対象にしない**（埋まる前提の設計のため）。
承認キューでは「体験3か所・要確認Nか所」を件数で表示する。
