# comparison_template.md — 比較モード（買い替え起点・スレッド型）

単品投稿とは別ルートの生成テンプレ。入力は `config/my_products.md` **のみ**。
楽天APIは「りんりんが挙げた商品と競合2つの事実（価格・レビュー数・容量）を取りに行く」
ためだけに使う。商品を**探させない**のがこのモードの要点。

## 出力の形（Threads：親1本＋ぶら下げ3本）

Threadsは1投稿500字。比較を1投稿に詰めると必ず薄くなるので、**スレッドに分ける**。
ぶら下げを3本置くとリンクの接触点が3回になり、楽天の「かご入れ24h」条件に対して
クリック機会が単純に3倍になる。比較モードをスレッドにする理由はこれ。

```
[親]   結論だけ。どれが誰向きかを3行。リンクは貼らない
 └[1]  商品A：向いている人 / 向いていない人 → リンク
 └[2]  商品B：向いている人 / 向いていない人 → リンク
 └[3]  商品C：向いている人 / 向いていない人 → リンク ＋ #PR
```

- **勝者を1つに決めない。** 状況別に3つとも「向いている人」を与える
  （1つに決めると、他2つのリンクが死ぬ。3リンクあることが収益上の意味）
- `#PR` は親とぶら下げ最終の両方に入れる（compliance_check.py が親に無ければ自動付与）
- 親は結論から始める。「比較しました」で始めない

## 親投稿の型（250〜350字）

```
①フック1行（買い替えの事実を先頭に。例：「◯◯を3年で2回買い替えて、やっと落ち着いた」）
②この投稿で何が決まるかを1行（「どれを買うかじゃなく、どれが自分向きかが決まる」）
③状況別の結論3行（「とにかく安く→A」「詰め替えの手間が嫌→B」「量を使う→C」）
④「詳細はぶら下げに」1行
```

## ぶら下げの型（各150〜220字・3本とも同じ構造）

```
①商品名 ＋【要確認：価格】【要確認：容量】
②向いている人（1行）
③向いていない人（1行）※ここを書くから信用される。必ず入れる
④【ここに体験：この商品で何が良かった／不満だったか】（りんりんが後から埋める）
⑤リンク
```

## プレースホルダ規約（このモードの安全装置）

AIは**体験と数値を書かない**。代わりに穴を空ける。埋めるのはりんりん。

| 記法 | 意味 | 誰が埋めるか |
|---|---|---|
| `【ここに体験：〜】` | 実際に使った感想。1つあたり1〜2行 | りんりん（3か所・5分） |
| `【要確認：〜】` | 価格・容量・サイズ。商品ページと突き合わせる | りんりん（目視） |

- **プレースホルダが残ったままの投稿は `compliance_check.py` が投稿をブロックする**
  （`--allow-placeholder` を付けた承認キュー生成時のみ警告に留める）
- 使っていない商品について実感を書かない。競合2商品の体験欄は
  「【ここに体験：使っていなければ削除】」とし、削除で通してよい
- 埋めなかった `【要確認：〜】` は、その一文ごと削除して投稿する（数値を推測で埋めない）

## 生成時の禁止事項（v4継承ルールの比較モード版）

- 楽天商品ページ・レビューに書かれていない仕様を書かない
- 「A社より優れている」等の他社比較の断定を書かない（景表法・比較広告）
- レビューを根拠にするときは「レビューでは〜という声」形式を必ず経由する
- 3商品の優劣を点数化しない（「A：85点」等は根拠のない優良誤認になりうる）

## 再利用（2本目以降）

`my_products.md` の記入欄を別カテゴリに差し替えるだけ。テンプレ側は一切変えない。
同じカテゴリで2本目を作らない（重複判定に引っかかる＋読者が同じ）。
